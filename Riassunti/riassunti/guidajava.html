1. Introduzione a Java e Ambiente di Sviluppo

Cos'è la Programmazione

La programmazione è il processo di ideazione, progettazione e costruzione di programmi informatici volti alla risoluzione di problemi o allo svolgimento di computazioni. La programmazione comprende diverse fasi:

  • Analisi del problema
  • Generazione di algoritmi
  • Studio dell'accuratezza e del consumo di risorse
  • Implementazione (fase nota come coding)

Paradigmi di Programmazione

Paradigma Caratteristiche
Procedurale Sequenze di istruzioni e funzioni che operano su dati
Object Oriented (OOP) Organizza il codice in oggetti con stato e comportamento

Java: Caratteristiche Principali

Java è un linguaggio di programmazione:

  • Alto livello: sintassi comprensibile e astratta dall'hardware
  • Orientato agli oggetti: modella il software tramite classi e oggetti
  • Tipizzazione statica: i tipi vengono controllati a compile-time

Storia di Java

  • Creato da James Gosling alla Stanford University agli inizi degli anni '90
  • 1992: nasce il linguaggio Oak (quercia) sviluppato da Sun Microsystems
  • Nome successivamente cambiato in Java (varietà di caffè indonesiana)
  • 2010: Sun Microsystems acquisita da Oracle

Vantaggi di Java

  • Portabilità: esegue su diverse piattaforme senza modifiche
  • Sicurezza: gestione della memoria e controlli di tipo avanzati
  • Gestione errori: sistema di eccezioni robusto
  • Popolarità: uno dei linguaggi più usati per applicazioni enterprise
  • Versatilità: sviluppo desktop, mobile (Android), web, server

Bytecode e Compilazione

Il bytecode è il linguaggio intermedio tra il codice sorgente Java e la JVM:

  • File .java → compilatore javac → bytecode (file .class)
  • Viene eseguito dalla JVM su qualsiasi piattaforma
  • Consente la portabilità del codice ("Write Once, Run Anywhere")

Java Virtual Machine (JVM)

La JVM è il cuore dell'ecosistema Java:

  • Interpreta ed esegue il bytecode
  • Gestisce la memoria dinamica con la Garbage Collection
  • Rimuove automaticamente oggetti inutilizzati dalla memoria
  • Garantisce la portabilità del codice Java
  • Supporta altri linguaggi (Kotlin, Scala, Groovy)

Compilatore, Interprete e JIT

Java utilizza un approccio ibrido:

  1. Compilazione: il codice sorgente viene compilato in bytecode
  2. Interpretazione: la JVM interpreta il bytecode riga per riga
  3. JIT (Just-In-Time) Compiler: compila "a caldo" le parti di bytecode più utilizzate in codice nativo ottimizzato per massimizzare le performance

Questo approccio combina la portabilità dell'interpretazione con le prestazioni della compilazione nativa.

Componenti dell'Ecosistema Java

Componente Descrizione
JVM Macchina virtuale che esegue il bytecode
JRE JVM + librerie standard, sufficiente per eseguire programmi
JDK JRE + strumenti di sviluppo (javac, debugger, ecc.)

JVM (Java Virtual Machine)

La macchina virtuale che esegue bytecode.

JRE (Java Runtime Environment)

  • JVM + librerie standard di Java
  • File di supporto necessari per eseguire il codice
  • Sufficiente per l'utente finale che vuole solo eseguire programmi
  • Non include strumenti per sviluppare nuove applicazioni

  • JRE + strumenti di sviluppo completi
  • Compilatore (javac), debugger, strumenti di profiling
  • Necessario per gli sviluppatori che vogliono creare applicazioni
  • Permette di scrivere, compilare ed eseguire codice Java

Introduzione al Debugging

Il debugging è il processo di identificazione e risoluzione dei bug (errori nel codice che causano comportamenti inattesi).

Strumenti Principali

  1. System.out.println() per debugging basilare
  2. Debugger integrato nell'IDE
  3. Logger per applicazioni complesse

Debugging in IntelliJ IDEA

1. Impostare Breakpoint

  • Click sul margine sinistro della linea di codice (appare un punto rosso)
  • Shortcut: Ctrl+F8 (Windows/Linux) o Cmd+F8 (Mac)
  • Click destro sul breakpoint per condizioni avanzate

2. Avviare il Debug

  • Click sull'icona del bug verde (o seleziona "Debug" invece di "Run")
  • Shortcut: Shift+F9 (Windows/Linux) o Ctrl+D (Mac)

3. Controlli di Esecuzione

Comando Azione
Step Over (F8) Esegue la linea corrente
Step Into (F7) Entra nel metodo
Step Out (Shift+F8) Esce dal metodo corrente
Resume (F9) Continua fino al prossimo breakpoint

4. Ispezione Variabili

Durante il debug è possibile:

  • Visualizzare lo stack di chiamate
  • Ispezionare i valori delle variabili
  • Valutare espressioni al volo
  • Modificare valori durante l'esecuzione

2. Basi di Java: Tipi, Variabili e Operatori

Tipi di Dato Primitivi

I tipi primitivi sono i mattoni fondamentali di Java. Non sono oggetti e risiedono nello stack per massima efficienza.

Tipo Dimensione Range
byte 8 bit -128 a 127
short 16 bit -32,768 a 32,767
int 32 bit -2,147,483,648 a 2,147,483,647
long 64 bit ±9 × 1018 circa
float 32 bit Singola precisione (7 cifre)
double 64 bit Doppia precisione (15 cifre)

// Tipi numerici
int numero = 10;
float decimale = 3.14f;
double precisione = 3.14159265359;
long grande = 9223372036854775807L;

// Altri tipi
boolean flag = true;
char carattere = 'C';
String testo = "Hello World";

// Auto-boxing
Integer oggetto = 42;       // int → Integer
int primitivo = oggetto;    // Integer → int

Conversioni tra Tipi

Auto-boxing

Conversione automatica tra tipi primitivi e wrapper classes (classi involucro):

Auto-boxing e unboxing
int primitivo = 42;
Integer oggetto = primitivo;       // auto-boxing: int → Integer
int nuovoPrimitivo = oggetto;      // unboxing: Integer → int

Casting Esplicito

Conversione forzata tra tipi compatibili:

Casting
double decimale = 3.14;
int intero = (int) decimale;       // casting: 3.14 → 3 (troncamento)

Variabili

Le variabili sono contenitori per dati che hanno un tipo, un nome e un valore.

Regole di Naming

  1. Devono iniziare con una lettera (o _ o $)
  2. Possono contenere lettere, numeri e underscore
  3. Sono case-sensitive: nome ≠ Nome
  4. Non possono essere parole riservate di Java (int, class, public, ecc.)

Operatori

Operatori Aritmetici

Operatore Operazione Esempio
+ Somma 5 + 3 → 8
- Sottrazione 5 - 3 → 2
* Moltiplicazione 5 * 3 → 15
/ Divisione 5 / 3 → 1 (intera)
% Modulo (resto) 5 % 3 → 2
Esempi di operatori
int a = 10, b = 3;

int somma = a + b;          // 13

import java.util.Scanner;

3. Controllo di Flusso: Condizioni e Cicli

Istruzioni Condizionali

if

Esegue un blocco di codice solo se la condizione è true:

if semplice
int numero = 5;

if (numero > 0) {
    System.out.println("Il numero è positivo");
}

if-else

Gestisce due percorsi di esecuzione mutuamente esclusivi:

if-else
int numero = -3;

if (numero >= 0) {
    System.out.println("Non è negativo");
} else {
    System.out.println("Il numero è negativo");
}

if-else if-else

Gestisce più casi ordinati. L'ordine delle condizioni è critico: la prima condizione true viene eseguita, le altre vengono saltate.

if-else-if
int numero = 25;

if (numero > 0) {
    System.out.println("Positivo");
} else if (numero < 0) {
    System.out.println("Negativo");
} else {
    System.out.println("Zero");
}

// Operatore ternario
String risultato = (numero % 2 == 0) ? "Pari" : "Dispari";
System.out.println(risultato);
Attenzione all'ordine:
Ordine scorretto
int numero = 25;

if (numero >= 0) {
    System.out.println("Poco");      // Eseguito per 25!
} else if (numero > 20) {
    System.out.println("Tanto");     // Mai raggiunto
} else {
    System.out.println("Negativo");
}

switch-case

Alternativa più leggibile a catene di if su valori discreti:

switch-case
int giorno = 3;

switch (giorno) {
    case 1:
        System.out.println("Lunedì");
        break;
    case 2:
        System.out.println("Martedì");
        break;
    case 3:
        System.out.println("Mercoledì");
        break;
    case 4:
        System.out.println("Giovedì");
        break;
    case 5:
        System.out.println("Venerdì");
        break;
    default:
        System.out.println("Weekend!");
}

Importante: il break è fondamentale per evitare il fall-through (esecuzione dei case successivi).

Blocchi di Codice e Scope

Un blocco di codice è delimitato da parentesi graffe { }:

  • Introduce uno scope: variabili dichiarate nel blocco sono visibili solo lì
  • Previene collisioni di nomi
  • Aiuta l'incapsulamento a livello di metodo
Scope esempio
if (true) {
    int numero = 42;
    System.out.println(numero);        // Visibile
}

// System.out.println(numero);        // ERRORE: numero non visibile

Nesting di Strutture

È possibile annidare if, cicli e switch dentro altri blocchi:

Nesting
int numero = 10;

if (numero > 0) {
    if (numero % 2 == 0) {
        System.out.println("Numero positivo e pari");
    }
}

Best practice:

  • Mantieni il codice leggibile con adeguata indentazione
  • Evita livelli di nesting troppo profondi
  • Considera l'estrazione di metodi ausiliari se il nesting diventa eccessivo

Cicli

Ciclo for

Usato quando si conosce il numero di iterazioni:

for loop
for (int i = 0; i < 5; i++) {
    System.out.println("Iterazione: " + i);
}

Struttura:

  • Inizializzazione: int i = 0
  • Condizione: i < 5
  • Incremento: i++

Ciclo while

Esegue finché la condizione è true, controllandola prima di ogni iterazione:

while loop
int i = 0;

while (i < 5) {
    System.out.println("Iterazione: " + i);
    i++;
}

Ciclo do-while

Garantisce almeno un'esecuzione del corpo, controllando la condizione in coda:

do-while loop
int i = 0;

do {
    System.out.println("Iterazione: " + i);
    i++;
} while (i < 5);

break e continue

break

Esce immediatamente dal ciclo corrente:

for, while, do-while
// Ciclo for
for (int i = 0; i < 5; i++) {
    System.out.println("Iterazione: " + i);
}

// Ciclo while
int i = 0;
while (i < 5) {
    System.out.println("Iterazione: " + i);
    i++;
}

// Ciclo do-while (esegue almeno una volta)
int j = 0;
do {
    System.out.println("Iterazione: " + j);
    j++;
} while (j < 5);

// break e continue
for (int k = 0; k < 10; k++) {
    if (k == 4) continue;    // Salta il 4
    if (k == 8) break;       // Esce al 8
    System.out.println(k);
}

continue

Salta all'iterazione successiva, eseguendo subito l'aggiornamento/controllo del ciclo:

continue
int i = 0;
while (i < 10) {
    if (i == 4) {
        i++;
        continue;                      // Salta la stampa di 4
    }
    System.out.println(i);
    i++;
}
// Output: 0, 1, 2, 3, 5, 6, 7, 8, 9

Cicli Annidati e Complessità

Esempio di ciclo annidato:

Cicli annidati
for (int i = 0; i < 3; i++) {
    for (int j = 0; j < 2; j++) {
        System.out.println("i: " + i + ", j: " + j);
    }
}
Attenzione alla complessità computazionale: cicli annidati portano spesso a complessità O(n²) o superiore. Va bene per dataset piccoli, ma può diventare problematico su quelli grandi.

4. Strutture Dati

Array

Un array è una struttura dati che memorizza una raccolta di elementi dello stesso tipo.

Proprietà Principali

  1. Dimensione fissa: definita alla creazione, non modificabile
  2. Tipi omogenei: tutti gli elementi dello stesso tipo
  3. Indicizzazione: accesso tramite indice da 0 a lunghezza - 1
  4. Accesso diretto: tempo O(1) per accedere a qualsiasi elemento

Dichiarazione e Inizializzazione

Uso degli array
// Dichiarazione e inizializzazione
int[] numeri = {1, 2, 3, 4, 5};
String[] nomi = new String[3];

// Accesso agli elementi
System.out.println(numeri[0]);     // Primo elemento
numeri[1] = 42;                    // Modifica
System.out.println(numeri.length); // Lunghezza: 5

// Scorrere un array
for (int i = 0; i < numeri.length; i++) {
    System.out.println(numeri[i]);
}

// For-each (solo lettura)
for (int numero : numeri) {
    System.out.println(numero);
}

// Array multidimensionali
int[][] matrice = {
    {1, 2, 3},
    {4, 5, 6},
    {7, 8, 9}
};
System.out.println(matrice[1][2]); // Output: 6

Scorrere un Array

Ciclo for classico (può modificare elementi):

for con indice
int[] numeri = {10, 20, 30};

for (int i = 0; i < numeri.length; i++) {
    numeri[i] = numeri[i] * 2;     // Modifica effettiva
    System.out.println(numeri[i]);
}

Ciclo for-each (solo lettura):

for-each
for (int numero : numeri) {
    numero *= 2;                   // NON modifica l'array originale (lavora su copia)
    System.out.println(numero);
}
Importante: il for-each lavora su una copia del valore (passato per valore, non per riferimento), quindi le modifiche non hanno effetto sull'array originale.

ArrayList

Le collezioni come ArrayList offrono flessibilità rispetto agli array tradizionali.

Vantaggi

  • Dimensione dinamica: cresce automaticamente
  • Metodi utili: add, remove, get, size, contains

Svantaggio

  • Leggermente meno efficiente degli array (overhead di gestione dinamica)
Liste dinamiche
import java.util.ArrayList;

ArrayList<String> nomi = new ArrayList<>();

// Aggiunta elementi
nomi.add("Anna");
nomi.add("Luca");
nomi.add("Marco");

// Accesso
String primo = nomi.get(0);
int dimensione = nomi.size();

// Rimozione
nomi.remove("Anna");
nomi.remove(0);

// Verifica presenza
boolean contiene = nomi.contains("Luca");

// Iterazione
for (String nome : nomi) {
    System.out.println(nome);
}

LinkedList

Una lista doppiamente collegata: ogni nodo ha riferimenti al successivo e al precedente.

Caratteristiche

  • Inserimento/rimozione in testa/coda molto veloce: O(1)
  • Accesso per indice più lento di ArrayList: O(n) (deve scorrere i nodi)

Utilizzo

LinkedList
import java.util.LinkedList;

LinkedList<String> lista = new LinkedList<>();

lista.add("A");
lista.add("B");
lista.addFirst("Inizio");          // Aggiunge in testa
lista.removeFirst();               // Rimuove il primo elemento

Set (HashSet, TreeSet)

Una collezione che non consente elementi duplicati.

Tipologie Principali

Tipo Caratteristiche
HashSet Hash table, nessun ordine, operazioni O(1) mediamente
TreeSet Albero bilanciato, elementi ordinati, operazioni O(log n)

Esempio HashSet

HashSet
import java.util.HashSet;

HashSet<String> set = new HashSet<>();

set.add("A");
set.add("B");
set.add("A");                      // Ignorato (duplicato)

System.out.println(set.size());    // Output: 2

Map (HashMap, TreeMap)

Una collezione che associa chiavi a valori (dizionario).

Tipologie Principali

Tipo Caratteristiche
HashMap Chiavi non ordinate, accesso O(1) mediamente
TreeMap Chiavi ordinate, operazioni O(log n)

Esempio HashMap

Mappe chiave-valore
import java.util.HashMap;

HashMap<String, Integer> voti = new HashMap<>();

// Inserimento
voti.put("Mario", 28);
voti.put("Laura", 30);
voti.put("Giuseppe", 25);

// Accesso
int votoMario = voti.get("Mario");

// Verifica chiave
boolean presente = voti.containsKey("Laura");

// Iterazione
for (String nome : voti.keySet()) {
    System.out.println(nome + ": " + voti.get(nome));
}

// Rimozione
voti.remove("Giuseppe");

Stack

Struttura LIFO (Last-In-First-Out): l'ultimo elemento inserito è il primo ad essere estratto.

Operazioni Principali

  • push(): inserisce in cima
  • pop(): rimuove dalla cima
  • peek(): legge la cima senza rimuovere

Utilizzo

Stack
import java.util.Stack;

Stack<Integer> stack = new Stack<>();

stack.push(1);
stack.push(2);
stack.push(3);

System.out.println(stack.pop());       // Output: 3
System.out.println(stack.peek());      // Output: 2 (non rimuove)

Applicazioni: backtracking, parsing, gestione chiamate ricorsive (call stack).

Queue

Struttura FIFO (First-In-First-Out): il primo elemento inserito è il primo ad essere estratto.

Operazioni Principali

  • add()/offer(): inserisce (enqueue)
  • poll()/remove(): estrae (dequeue)
  • peek(): legge il primo senza rimuovere

Utilizzo

Queue
import java.util.LinkedList;
import java.util.Queue;

Queue<String> queue = new LinkedList<>();

queue.add("A");
queue.add("B");
queue.add("C");

System.out.println(queue.poll());      // Output: A
System.out.println(queue.peek());      // Output: B

Applicazioni: gestione task, buffer, BFS (Breadth-First Search).

5. Fondamenti della Programmazione Orientata agli Oggetti

Cos'è la OOP

La Programmazione Orientata agli Oggetti (OOP) è un paradigma che organizza il codice in "oggetti":

  • Gli oggetti contengono sia dati (attributi) che codice (metodi)
  • Il software è una collezione di oggetti che interagiscono tra loro
  • La OOP riflette il mondo reale: oggetti con caratteristiche e comportamenti

Pilastri della OOP

  1. Incapsulamento: nascondere i dettagli implementativi
  2. Ereditarietà: riutilizzo del codice tramite gerarchie
  3. Polimorfismo: comportamenti diversi con stessa interfaccia

Classe vs Oggetto

Classe Oggetto
Template/modello per creare oggetti Istanza concreta di una classe
Definisce attributi e comportamenti Ha uno stato specifico
Tipo di dato astratto Occupa memoria
Entità concreta

Attributi

Gli attributi (o campi) rappresentano lo stato di un oggetto.

Caratteristiche

  • Sono variabili dichiarate nella classe
  • Possono avere diversi tipi (primitivi o riferimenti)
  • Hanno valori di default se non inizializzati
  • Possono avere modificatori di accesso

Valori di Default

Tipo Valore Default
Numerici interi 0
Numerici decimali 0.0
boolean false
Riferimenti (oggetti) null

Metodi

I metodi rappresentano il comportamento di un oggetto.

Caratteristiche

  • Sono funzioni definite nella classe
  • Hanno una firma: nome + parametri + tipo di ritorno
  • Possono accedere agli attributi della classe
  • Possono essere pubblici o privati

Costruttori

I costruttori sono metodi speciali per inizializzare oggetti quando vengono creati.

Caratteristiche

  • Hanno lo stesso nome della classe
  • Non hanno tipo di ritorno
  • Vengono chiamati con l'operatore new
  • Possono essere multipli (overloading)
  • Se non definiti, Java fornisce un costruttore di default senza parametri

Il Riferimento this

Il riferimento this punta all'istanza corrente dell'oggetto.

Utilizzi

  1. Disambiguare tra attributi e parametri
  2. Chiamare altri costruttori della stessa classe
  3. Passare l'oggetto corrente come parametro

Modificatori di Accesso

I modificatori di accesso controllano la visibilità di classi, metodi e attributi.

Modificatore Stessa classe Stesso package Sottoclasse Ovunque
private ✓ ✗ ✗ ✗
default ✓ ✓ ✗ ✗
protected ✓ ✓ ✓ ✗
public ✓ ✓ ✓ ✓

Descrizione

  • public: accessibile da qualsiasi classe
  • private: accessibile solo dalla classe stessa
  • protected: accessibile dal package e dalle sottoclassi
  • default (nessun modificatore): accessibile solo dal package

Incapsulamento

L'incapsulamento è un principio fondamentale della OOP.

Obiettivi

  • Nascondere i dettagli implementativi
  • Combinare dati e metodi che li manipolano
  • Proteggere l'integrità dei dati
  • Fornire un'interfaccia controllata

Best Practices

  1. Attributi private

public class Car {

    private String brand;
    private String model;
    private int year;
    private double speed;

        this.model = model;
        this.year = year;
        this.speed = 0.0;
    }

    public Car(String brand, String model) {

    }

        this.speed += increment;
        System.out.println("Velocità attuale: " + speed + " km/h");
    }
    
    public void brake(double decrement) {
        this.speed = Math.max(0, this.speed - decrement);
        System.out.println("Velocità attuale: " + speed + " km/h");
    }
    
    // Getter e Setter
    public String getBrand() {
        return brand;
    }
    
    public void setBrand(String brand) {
        if (brand != null && !brand.isEmpty()) {
            this.brand = brand;
        }
    }
    
    public double getSpeed() {
        return speed;
    }
    
    // Metodo toString
    @Override
    public String toString() {
        return brand + " " + model + " (" + year + ")";
    }
}

6. Interfacce, Classi Astratte e Classi Annidate

Metodi Default nelle Interfacce

Da Java 8, le interfacce possono contenere metodi con implementazione usando la parola chiave default.

Vantaggi

  • Permettono di aggiungere nuovi metodi senza rompere le classi esistenti
  • Non richiedono override obbligatorio
  • Possono accedere ad altri metodi dell'interfaccia
  • Non possono accedere a variabili di stato

Interfacce

Definizione e implementazione
// Interfaccia
public interface Animal {
    // Metodi astratti (implicitamente public abstract)
    void makeSound();
    void eat();
    
    // Metodo default (Java 8+)
    default void sleep() {
        System.out.println("L'animale sta dormendo...");
    }
    
    // Metodo statico
    static void info() {
        System.out.println("Interfaccia Animal");
    }
}

// Implementazione
public class Dog implements Animal {
    private String name;
    
    public Dog(String name) {
        this.name = name;
    }
    
    @Override
    public void makeSound() {
        System.out.println(name + " dice: Bau Bau!");
    }
    
    @Override
    public void eat() {
        System.out.println(name + " sta mangiando crocchette");
    }
    
    // sleep() è ereditato (override opzionale)
}

// Uso
Dog dog = new Dog("Rex");
dog.makeSound();
dog.eat();
dog.sleep();
Animal.info();

Interfacce vs Classi Astratte

Quando Usare Interfacce

  • Vuoi definire un contratto (cosa fare, non come)
  • Classi non correlate devono avere comportamenti comuni
  • Serve ereditarietà multipla di tipo
  • Definisci solo comportamenti senza stato

Quando Usare Classi Astratte

  • Hai codice comune da condividere tra sottoclassi
  • Vuoi uno stato comune nelle sottoclassi
  • Hai una gerarchia di classi correlate
  • Vuoi fornire un'implementazione base parziale

    public double getPerimeter() {

}

Static Nested Classes (Classi Statiche Nidificate)

  • Dichiarate static dentro un'altra classe
  • Non hanno accesso ai membri di istanza della classe esterna
  • Usate per raggruppare logicamente classi correlate
  • Utili per pattern come il Builder
Static nested class
public class OuterClass {
    private static String msg = "Hello";
    private String instanceMsg = "World";
    
    // Static nested class
    public static class StaticNested {
        public void display() {

            // System.out.println(instanceMsg); // ERRORE!

// Uso:

  • Non static, dichiarate dentro una classe
  • Hanno accesso a tutti i membri della classe esterna (anche private)
  • Usate quando la classe è strettamente legata all'outer class
  • Utili per gestione eventi

7. Gestione delle Eccezioni e Debugging

Introduzione alle Eccezioni

Un'eccezione è un evento che interrompe il normale flusso di esecuzione di un programma. In Java, le eccezioni sono oggetti che ereditano dalla classe Throwable.

Gerarchia delle Eccezioni

Gerarchia
Object
  └── Throwable
        ├── Error (unchecked)
        │     ├── OutOfMemoryError
        │     └── StackOverflowError
        └── Exception
              ├── RuntimeException (unchecked)
              │     ├── NullPointerException
              │     ├── IllegalArgumentException
              │     ├── ArithmeticException
              │     └── IndexOutOfBoundsException
              └── Other Exceptions (checked)
                    ├── IOException
                    ├── FileNotFoundException
                    ├── SQLException
                    └── ClassNotFoundException

Categorie Principali

  1. Error: problemi gravi a livello di sistema (non gestibili dall'applicazione)
  2. Exception: problemi recuperabili (gestibili dal programmatore)
  3. RuntimeException: errori di programmazione (unchecked)

Checked vs Unchecked Exceptions

Checked Exceptions Unchecked Exceptions
Devono essere gestite obbligatoriamente Non richiedono gestione obbligatoria
try-catch o throws richiesto Possono propagare liberamente
Controllate dal compilatore Non controllate dal compilatore
Es: IOException, SQLException Es: RuntimeException e sottoclassi
NullPointerException
ArrayIndexOutOfBoundsException

Gestire le Eccezioni con try-catch

Gestione eccezioni
import java.io.*;

public class ExceptionExample {
    public static void main(String[] args) {
        // Try-catch base
        try {
            int result = 10 / 0;
        } catch (ArithmeticException e) {
            System.out.println("Errore: divisione per zero!");
        }
        
        // Try-catch multipli
        try {
            String text = null;
            System.out.println(text.length());
        } catch (NullPointerException e) {
            System.out.println("Riferimento nullo!");
        } catch (Exception e) {
            System.out.println("Errore generico: " + e.getMessage());
        }
        
        // Try-with-resources (Java 7+)
        try (BufferedReader reader = new BufferedReader(
                new FileReader("file.txt"))) {
            String line = reader.readLine();
            System.out.println(line);
        } catch (IOException e) {
            System.out.println("Errore I/O: " + e.getMessage());
        }
        // reader.close() chiamato automaticamente
    }
}

Il Blocco finally

Il blocco finally viene eseguito sempre, anche in caso di eccezione o return.

finally
FileReader fr = null;
try {
    fr = new FileReader("test.txt");
    // Operazioni sul file
} catch (IOException e) {
    System.out.println("Errore: " + e.getMessage());
} finally {
    // Viene eseguito SEMPRE
    if (fr != null) {
        try {
            fr.close();
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}

throw vs throws

throw (nel corpo del metodo)

  • Lancia un'eccezione in un punto specifico
  • Crea una nuova istanza dell'eccezione
  • Interrompe l'esecuzione del metodo
  • Passa il controllo al blocco catch più vicino

throws (nella firma del metodo)

  • Dichiara che il metodo può generare quell'eccezione
  • Obbliga il chiamante a gestire l'eccezione (solo per checked exceptions)
  • Documentazione delle eccezioni possibili
Lanciare eccezioni
public class CustomException {
    // throws nella firma
    public static void validateAge(int age) throws IllegalArgumentException {
        if (age < 0) {
            // throw nel corpo
            throw new IllegalArgumentException(
                "L'età non può essere negativa: " + age
            );
        }
        if (age < 18) {
            throw new IllegalArgumentException(
                "Devi avere almeno 18 anni!"
            );
        }
        System.out.println("Età valida: " + age);
    }
    
    public static void main(String[] args) {
        try {
            validateAge(15);
        } catch (IllegalArgumentException e) {
            System.out.println("Eccezione catturata: " + e.getMessage());
        }
        
        try {
            validateAge(25);
        } catch (IllegalArgumentException e) {
            System.out.println("Non dovrebbe arrivare qui");
        }
    }
}

9. Generics e Iterator

Introduzione ai Generics

I Generics sono stati introdotti in Java 5 per fornire type-safety a compile-time.

Vantaggi

  • Permettono di creare classi, interfacce e metodi parametrizzati sul tipo
  • Type-safety in fase di compilazione
  • Eliminano la necessità di casting esplicito
  • Riutilizzo del codice con tipi diversi
  • Maggiore leggibilità e manutenibilità

Generics

Classi e metodi generici
// Classe generica
public class Box<T> {
    private T content;
    
    public void set(T content) {
        this.content = content;
    }
    
    public T get() {
        return content;
    }
}

// Metodo generico
public class Utils {
    public static <T> void printArray(T[] array) {
        for (T element : array) {
            System.out.print(element + " ");
        }
        System.out.println();
    }
}

// Uso
Box<String> stringBox = new Box<>();
stringBox.set("Hello");
String str = stringBox.get();  // No cast!

Box<Integer> intBox = new Box<>();
intBox.set(42);
Integer num = intBox.get();

Integer[] numbers = {1, 2, 3, 4, 5};
Utils.printArray(numbers);

Wildcard in Java Generics

Le wildcard sono simboli speciali (?) usati nei generics per rappresentare un tipo sconosciuto. Permettono di creare metodi e classi più flessibili.

Il Problema dell'Invarianza

I generics in Java sono invarianti: anche se Integer estende Number, List<Integer> non è un sottotipo di List<Number>.

Invarianza
List<Integer> ints = new ArrayList<>();
// List<Number> nums = ints;      // ERRORE di compilazione

Se fosse permesso, potremmo avere problemi di type-safety:

Problema type-safety
nums.add(3.14);                    // Metteremmo un Double in una List<Integer>!

Le wildcard risolvono questo problema con regole precise su lettura e scrittura.

Principio PECS

Producer Extends, Consumer Super:

  • Producer Extends: se la struttura produce valori per te → usa ? extends T
  • Consumer Super: se la struttura consuma valori da te → usa ? super T

Tipi di Wildcard

1. Wildcard Senza Limiti (?)

Rappresenta una lista di qualsiasi tipo.

Wildcard illimitata
public void printList(List<?> list) {
    for (Object obj : list) {
        System.out.println(obj);
    }
}

Cosa puoi fare:

  • Leggere: solo come Object
  • Scrivere: praticamente no (eccetto null)

Quando usarla: quando non ti interessa il tipo concreto, vuoi solo leggere/iterare senza modificare.

2. Upper Bound (? extends T)

Rappresenta una lista di qualsiasi tipo che sia T o sottoclasse di T.

Upper bound
public void processList(List<? extends Number> list) {
    for (Number number : list) {
        System.out.println(number.doubleValue());
    }
}

Accetta: List<Number>, List<Integer>, List<Double>, ecc.

Cosa puoi fare:

  • Leggere: sì, come T (o Object)
  • Scrivere: NO (tranne null)

Perché NON puoi scrivere:

Immagina di chiamare il metodo con List<Double>. Se potessi fare list.add(42) (che è Integer), staresti mettendo un Integer in una List<Double> → type safety violata!

Regola: con ? extends T la lista è un producer (produce valori di tipo T), non un consumer.

3. Lower Bound (? super T)

Rappresenta una lista di qualsiasi tipo che sia superclasse di T.

Lower bound
public void addToList(List<? super Integer> list) {
    list.add(42);
    list.add(new Integer(7));
}

Accetta: List<Integer>, List<Number>, List<Object>.

Cosa puoi fare:

  • Scrivere: sì, puoi aggiungere T (e sottotipi)
  • Leggere: solo come Object

Perché puoi scrivere:

È sempre sicuro aggiungere un Integer:

  • Se è List<Integer> → perfetto
  • Se è List<Number> → un Integer è un Number
  • Se è List<Object> → un Integer è un Object

Regola: con ? super T la lista è un consumer (consuma valori di tipo T), non un producer tipizzato.

Schema Riassuntivo

Forma Accetta Leggere come Scrivere
List<?> Qualsiasi tipo Object Solo null
List<? extends T> T e sottotipi T Solo null
List<? super T> T e supertipi Object T e sottotipi

Quando Usare Cosa

  • Metodo che solo legge da una lista → List<? extends T> o List<?>
  • Metodo che solo aggiunge elementi di tipo T → List<? super T>
  • Metodo che legge e scrive con lo stesso tipo → List<T> con parametro di tipo normale

Esempio combinato:

Esempio combinato
<T> void copy(List<? extends T> src, List<? super T> dest) {
    for (T item : src) {
        dest.add(item);
    }
}

Wildcard

Upper e Lower Bound
import java.util.*;

public class WildcardExample {
    // Upper bound (? extends T)
    // Può LEGGERE come Number, NON può scrivere
    public static void printNumbers(List<? extends Number> list) {
        for (Number num : list) {
            System.out.println(num.doubleValue());
        }
        // list.add(42);  // ERRORE di compilazione!
    }
    
    // Lower bound (? super T)
    // Può SCRIVERE Integer, legge solo come Object
    public static void addIntegers(List<? super Integer> list) {
        list.add(42);
        list.add(100);
        // Integer num = list.get(0);  // ERRORE!
        Object obj = list.get(0);      // OK
    }
    
    // Wildcard senza limiti
    public static void printList(List<?> list) {
        for (Object obj : list) {
            System.out.println(obj);
        }
    }
    
    public static void main(String[] args) {
        List<Integer> integers = Arrays.asList(1, 2, 3);
        List<Double> doubles = Arrays.asList(1.1, 2.2, 3.3);
        
        printNumbers(integers);  // OK
        printNumbers(doubles);   // OK
        
        List<Number> numbers = new ArrayList<>();
        addIntegers(numbers);    // OK
    }
}

Iterator

Iterazione su collezioni
import java.util.*;

public class IteratorExample {
    public static void main(String[] args) {
        List<String> list = new ArrayList<>();
        list.add("A");
        list.add("B");
        list.add("C");
        list.add("D");
        
        // Uso dell'Iterator
        Iterator<String> iterator = list.iterator();
        while (iterator.hasNext()) {
            String element = iterator.next();
            System.out.println(element);
            
            // Rimozione sicura durante iterazione
            if (element.equals("B")) {
                iterator.remove();
            }
        }
        
        System.out.println("Dopo rimozione: " + list);
        // Output: [A, C, D]
    }
}

10. Input/Output

Introduzione agli Stream di I/O

Uno stream è un flusso sequenziale di dati.

Caratteristiche

  • Unidirezionali: input o output, non entrambi
  • Sequenziali: i dati vengono letti/scritti in ordine
  • Possono essere bufferizzati o non bufferizzati

Tipi Principali

Tipo Uso
InputStream / OutputStream Dati binari (byte)
Reader / Writer Dati testuali (caratteri)

FileReader

    int character;

    }
}

Con BufferedReader (più efficiente)

BufferedReader
try (BufferedReader reader =

public class FileIOExample {

    }
}

Serializzazione degli Oggetti

La serializzazione è il processo di conversione di un oggetto in uno stream di byte.

Utilizzi

  • Persistenza degli oggetti su disco
  • Trasmissione in rete
  • Deep cloning di oggetti
Salvare e caricare oggetti
import java.io.*;

// Classe serializzabile
class Person implements Serializable {
    private static final long serialVersionUID = 1L;
    private String name;
    private int age;
    
    public Person(String name, int age) {
        this.name = name;
        this.age = age;
    }
    
    public String getName() { return name; }
    public int getAge() { return age; }
}

public class SerializationExample {
    public static void main(String[] args) {
        Person person = new Person("Mario Rossi", 30);
        
        // Serializzazione
        try (ObjectOutputStream oos = new ObjectOutputStream(
                new FileOutputStream("person.ser"))) {
            oos.writeObject(person);
            System.out.println("Oggetto salvato");
        } catch (IOException e) {
            e.printStackTrace();
        }
        
        // Deserializzazione
        try (ObjectInputStream ois = new ObjectInputStream(
                new FileInputStream("person.ser"))) {
            Person loaded = (Person) ois.readObject();
            System.out.println("Nome: " + loaded.getName());
            System.out.println("Età: " + loaded.getAge());
        } catch (IOException | ClassNotFoundException e) {
            e.printStackTrace();
        }
    }
}

Java NIO (New Input/Output)

Java NIO è un insieme di API introdotte come alternativa al tradizionale sistema di I/O basato su stream.

Vantaggi

  • Miglioramenti in performance e flessibilità
  • Gestione non bloccante
  • Operazioni su file più semplici
  • Integrazione con Stream API

Lettura e Scrittura con NIO

Files API

Java NIO

Modern I/O con Files e Paths
import java.nio.file.*;
import java.io.IOException;
import java.util.List;

public class NIOExample {
    public static void main(String[] args) {
        try {
            // Scrittura semplice
            String content = "Contenuto del file\nSeconda riga\nTerza riga";
            Path path = Paths.get("nio_output.txt");
            Files.write(path, content.getBytes());
            
            // Lettura completa
            List<String> lines = Files.readAllLines(path);
            System.out.println("Numero di righe: " + lines.size());
            
            // Lettura con stream
            Files.lines(path).forEach(System.out::println);
            
            // Informazioni sul file
            System.out.println("Esiste: " + Files.exists(path));
            System.out.println("Dimensione: " + Files.size(path) + " byte");
            System.out.println("Leggibile: " + Files.isReadable(path));
            
            // Copia e spostamento
            Path copy = Paths.get("nio_copy.txt");
            Files.copy(path, copy, StandardCopyOption.REPLACE_EXISTING);
            
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
